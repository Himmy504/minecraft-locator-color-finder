# Security policy

## Supported versions

Security fixes are applied to the latest release and the default branch. Older binaries may not receive patches.

## Reporting a vulnerability

Use GitHub's **Security → Report a vulnerability** feature when it is available. Do not disclose exploitable details in a public issue. If private vulnerability reporting is unavailable, open a public issue containing no sensitive details and ask the maintainer to establish a private contact channel.

Include the affected version, operating system, impact, reproduction prerequisites, and a minimal proof of concept. Do not include Minecraft/Microsoft credentials, bearer tokens, private player datasets, or unrelated personal information.

## Security boundaries

- The program does not require or accept Minecraft account credentials.
- Only UUIDs already matched locally are sent to Mojang's public profile endpoint when name verification is enabled.
- `--no-verify-names` prevents those verification requests.
- Dataset downloads are checked against a pinned byte length and SHA-1 value before use.
- Custom datasets are user-supplied and are not cryptographically authenticated by the program.
- Release archives include SHA-256 checksums generated by the release workflow.
